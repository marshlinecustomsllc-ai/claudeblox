No client script, no Touched detection, nothing. This fully blocked all play past the Lobby. Fixed: added server-side Touched detection on LobbyPad-tagged parts directly in SessionManager (with per-limb-Touched debounce, the same bug class fixed elsewhere in this project's pipeline history), sharing one setPlayerReady() function with the existing RequestReady remote handler so the two paths can't drift apart. Verified: compiles clean; user confirmed pads work after restarting Play.
- [x] CRITICAL: HearthManager's tickBurn had zero phase awareness -- it burned fuel at whatever rate was last set via SetBurnRate, which defaulted to Night 1's rate (2.0/s) from the moment the server booted. This meant the Hearth burned at full Night intensity through the entire Lobby wait AND the whole Day phase, often extinguishing itself (triggering Blackout) before Night 1 even began -- confirmed live via a real user playtest log ("wax refreshed for Night 1: 100/100" immediately followed by "blackout detected" 0.4s later). Fixed: added Config.HEARTH_DAY_BURN_RATE=0.5 (architecture: "0.5/s day"), changed HearthManager's default currentBurnRate to this Day rate instead of a Night rate, and CycleManager.enterDay() now re-applies it every Day phase (enterNight already correctly applied the real per-night rate). Verified: all touched scripts compile clean; live re-test still needed to confirm Night 1 no longer opens with an immediate Blackout.
- [x] HearthManager had no reset-between-runs function (a previously-flagged, deliberately-deferred gap) -- added M.ResetForRun() (Tier 1, full fuel, clears in-progress feed channels) and wired it into CycleManager.EndRun(). This is a real but secondary contributor to the immediate-Blackout symptom above (the day-burn-rate bug was the dominant cause since it affects even a server's very first run).
- [x] CRITICAL: pressing F to toggle the hand lantern did nothing visible. The architecture always called for a dedicated LanternController LocalScript, but it was never created -- server-side (RequestLanternState handling, fuel burn, IsPlayerLit) worked correctly the whole time, but there was zero visual representation: no PointLight, no lantern model, nothing attached to the character at all. Fixed: built LanternController (attaches a PointLight + a 35-degree-cone SpotLight for Focused Beam to a Head Attachment, so both naturally aim wherever the character faces with no per-frame aiming code), mirroring InputController's F-key cycle independently and self-correcting from InventoryUpdated's lanternFuel field if the server forces the mode off. Verified: compiles clean, script exists correctly alongside the other 3 client scripts. Found via a real human playtest.
